# Регламент постановки и выполнения задач на участок «Образец»

Производство БМ

## 1. Общие положения

**1.1.** Настоящий регламент определяет порядок постановки, приёмки, выполнения и закрытия задач на подбор цвета бетонной фасадной плитки.

**1.2.** Регламент обязателен к исполнению для всех руководителей проектов (РП) и сотрудников участка подбора цвета.

**1.3.** Единая точка входа для всех задач — корпоративная система управления проектами Planfix. Задачи, поставленные устно, через мессенджеры или по электронной почте, к исполнению не принимаются.

**1.4.** Все задачи создаются строго по шаблону «Образец».

**1.5.** Приём задач технологом осуществляется только в первую половину дня: с 9:00 до 13:00. Задачи, созданные после 13:00, считаются поступившими на следующий рабочий день.

**1.6.** Полный цикл подбора цвета занимает от одной до двух недель активной работы. Срок не учитывает время нахождения задачи в статусах «Требует уточнения» и «Отложенная».

**1.7.** Ответственным за приём, исполнение и фиксацию результата по задаче является технолог.

## 2. Используемые статусы задачи в Planfix

| Статус | Ответственный | Описание |
| --- | --- | --- |
| **Новая** | РП | Задача создана, ожидает первичной проверки технологом. |
| **Подбор цвета** | Технолог | Техническое задание (ТЗ) принято. Задача находится в активной стадии производственного цикла (заливка, сушка, корректировка рецептуры). |
| **Требует уточнения** | Технолог | ТЗ заполнено не полностью, отсутствуют обязательные вложения, данные противоречивы, либо в процессе подбора потребовались дополнительные вводные от РП. |
| **Отложенная** | Технолог | Работа по задаче приостановлена по одной из причин: РП не ответил на уточнение; технолог инициировал встречу для совместного отсмотра итераций после недели безуспешных попыток подбора; иная внешняя причина. |
| **Завершённая** | Технолог | Итоговая рецептура подобрана, планшет собран, полный пакет финальной документации загружен в задачу. Работа участка подбора цвета полностью окончена. |

## 3. Лимит активных задач

**3.1.** Одновременно в статусе «Подбор цвета» может находиться не более 7 (семи) задач.

**3.2.** Если на момент проверки новой задачи лимит исчерпан, технолог оставляет задачу в статусе «Новая» и добавляет комментарий: «Достигнут лимит активных задач (7/7). Задача будет запущена в работу после освобождения слота. Ориентировочное ожидание — [указать дату]».

**3.3.** Очерёдность запуска ожидающих задач из статуса «Новая» определяется по принципу FIFO (First In, First Out — первым пришёл, первым запущен), за исключением задач с пометкой «Срочно» и визой руководителя отдела. Срочные задачи запускаются вне общей очереди сразу после освобождения ближайшего слота.

**3.4.** Задачи, находящиеся в статусах «Требует уточнения» и «Отложенная», не учитываются в лимите активных задач.

## 4. Состав полного технического задания (ТЗ)

Руководитель проекта заполняет все обязательные поля при создании задачи в Planfix. Если обязательные поля не заполнены, технолог вправе сразу перевести задачу в статус «Требует уточнения».

| Поле задачи | Заполнение | Описание и требования |
| --- | --- | --- |
| **Фактура** | Обязательно | Например: 235, «Брик Амараж», «Травертин». |
| **Целевой цвет** | Обязательно | Эталон цвета по стандартизированной палитре: RAL Classic, NCS или иной стандарт, указанный в проекте. |
| **Файл-референс** | При наличии | Прикрепить рендер, фотографию или скан образца. Файл должен быть чётким, без цветовых фильтров и цифровой цветокоррекции. |
| **Цвет затирки** | При наличии | Код цвета затирки по RAL/NCS. Если затирка проектом не предусмотрена, указать: «Без затирки». |
| **Срочность** | Обязательно | Задачи с пометкой «Срочно» принимаются в работу только при наличии визы руководителя отдела РП. |

## 5. Поэтапный процесс выполнения задачи

### Этап 1. Принятие задачи (окно 9:00–13:00)

- РП создаёт задачу в статусе «Новая».
- В ближайшее приёмное окно (до 13:00 текущего дня или на следующий рабочий день) технолог проверяет комплектность ТЗ и вложений.
- Если ТЗ заполнено не полностью или данные некорректны: технолог переводит задачу в статус «Требует уточнения» с обязательным комментарием о том, каких именно данных не хватает.
- Если ТЗ полное, но лимит активных задач исчерпан (7/7): задача остаётся в статусе «Новая» с комментарием о лимите и ориентировочной дате запуска.
- Если ТЗ полное и слот свободен: технолог переводит задачу в статус «Подбор цвета», определяет стартовую рецептуру и выдаёт заливщикам план на изготовление образцов.
- Время ожидания ответа от РП: если задача находится в статусе «Требует уточнения» несколько дней, технолог вправе перевести её в статус «Отложенная» с указанием причины.

### Этап 2. Подбор цвета (1–2 недели активной работы)

После перехода в статус «Подбор цвета» начинается производственный цикл, состоящий из следующих повторяющихся шагов:

- Технолог выдаёт заливщикам план на заливку образцов.
- На следующий день производится распалубка, сушка и визуальная оценка полученных бетонных камней технологом.
- При несоответствии цвета эталону технолог корректирует рецептуру пигментов и запускает цикл заново. При любом исходе технолог отписывается в задаче.

**Правила этапа:**

- Все промежуточные результаты (фотографии рядом с эталоном) загружаются технологом в комментарии к задаче без смены статуса.
- Правило недели: если по истечении одной календарной недели (7 дней) непрерывных попыток подбора удовлетворительный результат не достигнут, технолог обязан:
  - перевести задачу в статус «Требует уточнения»;
  - инициировать встречу с РП для совместного отсмотра всех изготовленных итераций (выкрасок).
- После проведения встречи и получения от РП новых вводных (либо подтверждения приемлемости одного из существующих вариантов) задача возвращается в статус «Подбор цвета» для финализации.

### Этап 3. Утверждение и сборка планшета (до 1 суток)

- Как только цвет бетонных камней признан соответствующим ТЗ, технолог в течение 1 (одних) суток:
  - собирает планшет;
  - передаёт планшет РП (физически, а также уведомлением о готовности к отгрузке в Planfix).
- Сразу после передачи планшета задача переводится в статус «Завершённая».
- Функционал участка на этом исчерпан.

## 6. Закрытие задачи. Требования к финальной документации

**6.1.** Перевод задачи в статус «Завершённая» допустим только при наличии в ней полного комплекта финальной документации, загружаемой технологом.

**6.2.** Обязательный перечень вложений:

- Фото готового планшета.
- Рецептура.
- Рецептура затирки (при наличии).
- Технологические примечания — описание особых условий, обязательных к соблюдению при тиражировании.

После загрузки всех обязательных вложений технолог переводит задачу в статус «Завершённая».

## 7. Порядок действий при корректировке планшета

**7.1.** Если после передачи планшета РП и вынесения на согласование архитектору/заказчику получен отрицательный результат (планшет не принят), работа участка по исходной задаче не возобновляется.

**7.2.** Для выполнения корректировки РП обязан создать новую задачу по тому же шаблону «Подбор цвета». При создании необходимо соблюсти следующие требования:

- Прикрепить фотографию предыдущего (отклонённого) планшета и ссылку на исходную задачу.
- Приложить документ, скриншот переписки или текст с перечнем замечаний архитектора.
- В первом комментарии к новой задаче поставить ссылку на номер исходной (завершённой) задачи.

**7.3.** Созданная задача поступает в статус «Новая» и встаёт в общую очередь задач наравне со всеми остальными. На неё в полном объёме распространяются:

- лимит активных задач (не более 7);
- правило очерёдности FIFO;
- правило приёма задач (9:00–13:00).

**7.4.** Никаких приоритетов или внеочередного запуска задача на корректировку не имеет. Исходная задача остаётся в статусе «Завершённая» и не переоткрывается.
